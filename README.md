# install-on-iphone

Одна иконка на одно приложение: нажал — на айфон встаёт свежий `main` с GitHub.

## Создать иконку

```bash
/usr/bin/python3 make_app.py ~/projects/<проект>
```

Появится `~/Applications/Install <Имя>.app` с иконкой самого приложения. Её можно положить в Dock.
Если схем, команд подписи или айфонов несколько — `--scheme`, `--team`, `--iphone`. Другая ветка — `--branch`.
После правок в этом репозитории иконку нужно создать заново: код копируется внутрь неё.

## Что происходит по нажатию

1. В клоне проекта — только `git fetch` основной ветки (`main` или `master`): ветки, файлы и HEAD не меняются,
   агентам ничего не мешает. Нет сети — ставится та версия GitHub, что была при последней синхронизации.
   Незапушенные коммиты и незакоммиченные правки в сборку не попадают.
2. На время установки создаётся временная папка: worktree основной ветки (только исходники, история остаётся в клоне)
   и кэш сборки Xcode. Git-игнорируемые `*.xcconfig` (личная подпись) копируются из клона.
   После установки — и после ошибки тоже — папка уходит в корзину, а git забывает worktree. На диске ничего не остаётся;
   цена — каждая сборка с нуля.
3. Схема, приложение, bundle id и команда подписи определяются через `xcodebuild`. Из всех установленных Xcode
   берётся самый новый, который умеет собирать под подключённый айфон (`--xcode` — выбрать вручную).
4. Айфон: сначала подключённый, из них — по проводу. Не отвечает — открывается Xcode и закрывается после установки,
   если до этого был закрыт.
5. Подпись: закэшированные профили этого приложения откладываются, чтобы 7 дней бесплатной подписи считались
   с этой установки. Сборка упала — профили возвращаются, прошла — уходят в корзину. Без сети подпись не трогается.
6. Release-сборка ставится поверх старой, данные приложения сохраняются.
   Если сборка упала, её полный лог остаётся в `~/Library/Logs/install-on-iphone/`.
